# Архитектура кода RustCraft

Как код мода разложен по частям. Правила игры — в спецификации (`02-spec.md`), рамки движка — её раздел 7 и `docs/research/horizon-modding-capabilities.md`.

## Части

| Часть | Где | Что внутри | Зависит от игры |
| --- | --- | --- | --- |
| Правила | `mod/rustcraft/rules` — свой крейт бандла (`[[crate]]`, пакет `rustcraft-rules`) | Сеть магистрали (топология, дальность узлов, маршруты предметов, жидкостей и энергии), машины, склад, монорельс как граф. Числа берутся из таблицы настроек | Нет |
| Бандл | `mod/rustcraft` (`horizon-mixin.toml` и хелперы) | Миксины Horizon: регистрация блоков и предметов, блок-энтити, окна, тик контроллеров сети, сохранение, отчёты Path-of-craft-tree | Да |
| Ресурсы | `mod/content` | Контент-мод под тем же id: модели блоков из Blender, текстуры, языки | Нет кода |

Свой крейт бандла движок компилирует один раз и пересобирает только при его изменении, поэтому тяжёлый код живёт в нём, а в хелперах остаётся только связка с игрой. Крейт не может зависеть от path-крейтов и берёт зависимости из Cargo.lock Horizon (сейчас только serde). Для тестов на корне репозитория есть workspace, который включает только этот крейт (cargo test в корне).

Правила не знают о движке: они получают снимок мира (какие корпуса где стоят, что в гнёздах, какие машины на стыках) и возвращают решения (какой предмет куда перенести, сколько энергии кому дать, какой диагноз показать). Поэтому их можно писать и проверять тестами без сборки движка; бандл только переводит события игры в вызовы правил и обратно.

## Правила: модули

- `net::topology` — линии магистрали. Вход: корпуса с четырьмя гнёздами, узлы со ступенью. Выход: линии (связные группы корпусов), сети каналов по гнёздам и видам (M3), дальность от узлов (N3), диагнозы «Дальше предела узла» и «Нет узла магистрали». Узел ступеней 1–3 связывает противоположные грани парами (N4), узел последней ступени — все шесть граней (M12).
- `net::items` — перенос предметов по сети канала: стыки с режимом, фильтром и приоритетом (M7), раздача по кругу среди равных (M8), забор только при месте в приёмнике (M6), пропускная способность по самому слабому каналу (M10, M14).
- `net::fluids` — несколько жидкостей в канале по ступени (M13).
- `net::energy` — баланс цепи, пропорциональное замедление при нехватке (E3), питание вплотную (E10), структуры накопителей (E11).
- `machines` — машины среза 1: электропечь, дробилка, плавильня сплавов, автокрафтер; режимы, модули, диагнозы.
- `tuning` — все числа баланса одной таблицей; бандл читает её из файла данных.

## Бандл

Строится по образцу `prototypes/traversal`: модули правил подключаются как модули игры (`[[module]]`), миксины — именованные хуки или HEAD в функцию, если хук молчит для бандла без trait-мода. Сеть тикает контроллером на тике уровня, а не тиком каждого блока (раздел 7). Состояние сетей держится в памяти и восстанавливается из блок-энтити и вложений уровня при загрузке.

## Порядок

1. Правила `net::topology` и `net::items` с тестами.
2. Вертикальный срез бандла: корпус магистрали как блок, блок-энтити с гнёздами, окно стыка, сохранение, вход на выделенный сервер. Главный неизвестный риск — зрелость API машин в Horizon (разбор возможностей, таблица рисков).
3. Энергия и машины среза 1, склад, монорельс с капсулой (способ b2).

Сборку бандла запускает владелец (`--trust-native-code`). Проверки в игре Claude проводит сам ботами на dev-сервере.
