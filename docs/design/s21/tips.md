# Срез 0.21, поток «описание в подсказке»: заметки к выпуску

Повод — слова владельца: «У всех блоков добавь описание из мода прямо в игре… я делаю модули для блоков механизмов. А у них нет описания, когда я на них навожусь, что они делают. Например, модуль выхода там с каким-то шансом вроде как добавляется еще один ресурс… я это не прочитать не могу, не увидеть, потому что все быстро забирается». Правила — раздел 41 `docs/design/02-spec.md` (TT1–TT6).

## Для CHANGELOG

### Добавлено

- **Описание предметов в подсказке.** Наведи на любой блок или предмет RustCraft — в инвентаре, сундуке, окне машины, творческой вкладке — и под названием видно, что он делает: краткое описание из справочника. Модули ещё пишут свой главный показатель и куда ставятся.

## Как это сделано

- **Крючок движка.** В Horizon 7e4e421 есть точка `tooltip` (API 12, аналог `ItemTooltipEvent` NeoForge): `Game::native_tooltip(&self, stack, lines: &mut Vec<(Text, u32)>)`, `crates/horizon-client/src/game/native_hooks.rs:7911-7920`. Её зовёт сборка подсказки предмета после всех строк игры (`game/stations.rs:2622-2626`), везде, где игра показывает подсказку предмета: слоты, творческие вкладки, книга рецептов, наведение в чате. Каталог — `native-hooks.json` («tooltip», `contract: collect`, `out: lines`), описание — `docs/native-mods.md:207-209`. На неё же вешается JEI из сборки.
- **Внедрение.** `horizon-mixin.toml`: модуль `rustcraft_tips` (`mod/rustcraft/tips.rs`) и HEAD-внедрение `tooltip` с помощником `hook_tooltip.rs`, привязки как у JEI (`game`, `stack`, `lines`).
- **Правила** (`rules/src/tips.rs`, без игры):
  - `pages_of(item)` — страницы предмета: по `makes`, потом по `item`; ступени `_2…_4` — страница семейства (сначала id без ступени, потом `_2…_4`: броня и клинок начинаются со ступени 2); `ALIASES` — осколок, друза, затравка, якорь зиплайна.
  - `lines(item, lookup)` — строки: `.sum` каждой страницы, затем выбранные показатели (`STATS`, только модули). Русский — «ключ: значение» из показателей справочника, английский — `rustcraft.tip.<страница>.<номер>` (в en_us у страниц справочника есть только имя и краткое описание). Ключи `rustcraft.tip.*` не под `rustcraft.handbook.`, поэтому `assets/models/handbook_mc.py` их не стирает.
  - `WIDTH = 240` GUI-пикселей, `COLOR = 0xAAAAAA`.
- **Клиент** (`tips.rs`): строки на языке клиента (`horizon_client::lang`), перенос `handbook::wrap` по ширине шрифта игры (`native_text_width`), серые, вставляются после первой строки (названия). Кадр без выделений для чужих предметов: `pages_of` отвечает пустым списком по префиксу id.
- **Почему не `minecraft:lore`.** Строки в компоненте стака сделали бы старые стаки (без lore) и новые несовместимыми для складывания, а описание менялось бы только у новых стаков. Описание в подсказке ничего не пишет в стак и меняется вместе с файлами языка.

## Примеры (русский клиент, до переноса)

- Модуль выхода: «С шансом 15% машина не тратит ингредиент или даёт лишний продукт.» / «Дезинтегратор: Доля возврата 60% / 70%, не выше 75%» / «Подходит: Дробилка, печь, плавильня сплавов, дезинтегратор».
- Модуль отдачи: «Накопитель отдаёт энергию быстрее.» / «Отдача: +50% за модуль» / «Подходит: Накопитель».
- Модуль скорости: «Машина работает вдвое быстрее и тратит в 2,5 раза больше энергии.» / «Подходит: Всем машинам, кроме машин животных и рыбалки».
- Электропечь · ступень 3: «Плавит всё, что плавит обычная печь, без топлива и вдвое быстрее.»
- Осколок кристалла: «Выпадает из друз кристаллов под землёй.» / «Осколок кристалла, поставленный на бак с питательным раствором, вырастает в друзу.»

## Проверки

- Тесты правил `tips::tests` (6): у каждой модели предмета в `assets/rustcraft/items` есть страница и все строки на русском и английском; подсказка не длиннее 9 строк при ширине 240 (6 px на знак); ступени берут страницу семейства; чужие предметы ничего не получают; модуль выхода пишет 15% и «Подходит»; выбранные показатели есть в справочнике, английская строка каждого называет те же числа, лишних английских строк нет, в русском копий нет.
- Сервер стенда компилирует тот же `horizon-client` с внедрением (`joint.ps1 try -Path`), самотесты не меняются: подсказка только клиентская.
